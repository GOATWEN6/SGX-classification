## 建议批准的一轮上限

以下是**新建议，尚未批准**；不沿用历史调用额度。

|项目|探索批次建议|
|---|---|
|模型|Qwen 固定快照一个；GLM 后置对照|
|图片|6 张固定参考 + 20 张探索；14 张保留完全不调用|
|步骤|逐步上传/抽取 → 历史/参考复核 → 至多 4 次说明更新 → 1 次指认或纠错 → 一次不变查看检查|
|候选|每个受影响图最多 4 张历史/参考图；双图复核；记录全部遗漏|
|整批请求|最多 300 次（含抽取、关系复核、增量与指认纠错）|
|重试|0；失败先审计，修复后如需重跑另给清单|
|Token|整批输入 ≤10,000,000，输出 ≤614,400；每请求输出 ≤2,048|
|记账费率|先按最高普通档 ¥1.2/¥12 每百万保守预留，执行前重验|
|费用|整批预留/实报记账 ≤¥20；上述 Token 顶格约 ¥19.37，不是预计一定花这么多|
|耗时|整批最多 30 分钟；每请求最多 60 秒；串行执行|

26 图冷启动最多约 26 次抽取 + min(325,26×4)=104 次复核，即 130 次；4 次单图说明变化约再 20 次；指认/纠错可能影响既有多条人物边，最多再约 104 次。约 254 次的设计空间包含在 300 次总上限中。实际按完整清单预检报告重新计数，缓存命中和成对去重会减少数量；不能只报“每张一次”的成本。

预留 Token 使用图片数量和上下文长度的保守工程估计，**不是供应商 Token 硬上界**。若某次实报超过估计，保留真实 usage 并立即停止后续工作；失败缺少 usage 时保留预留并标记，最后对照供应商账单。费用上限防止继续发请求，无法撤销已发请求的账单。若要求绝对账单上限，应由账号侧另设可用额度，不以此脚本代替。

单次输入或输出超过预留时，即使总限额仍充足，也返回 `RESERVATION_OVERRUN` 并停止任务/批次后续调用；记录保留 reservation、实报用量与 reservationExceeded。等于预留不算超出。若同时超过总上限则返回 `BUDGET_OVERRUN`。这项行为已有预算对象、真实模式编排及批次 CLI 的本地桩回归，详见 [审阅修复记录](CLASSIFICATION_STAGE_A_VERIFICATION.md)。

## 可运行的预检与评测

契约：`harness/classification/stage-a-evaluation.mjs` 导出的 ManifestSchema / TruthSchema / ApprovalSchema；入口：`npm run classification:eval`。图片文件只读，最多 1 MiB/张，实际字节 SHA-256 必须吻合；本轮不进行图片改造。真实图片如需调整尺寸，先形成受控派生文件和哈希。

```sh
npm run classification:eval -- --help
npm run classification:eval -- --manifest /绝对路径/batch.json --out /private/tmp/sgx-d4-preflight-新编号
```

默认只预检，不读取凭据，不联网。输出目录必须不存在，防止覆盖失败证据。检查材料与真值哈希、分区泄漏、主体范围、评测对象、价格核验时间和计划调用范围。缺少材料或仍为 draft 时不放行。

batch.json 结构：version/batchId/status/partition、provider/model/providerUseReviewRef、prices、caps、truth 文件路径及哈希、photos（Photo + 本地路径 + split + leakageGroup + 外发/人物授权引用）、tasks（taskId + 完整 Request + evaluatePhotoIds + expectedUnchangedPhotoIds）。tasks 支持逐次上传、补充说明、指认/纠错及查看；相同 scope 的任务复用算法快照。

truth.json 含独立 reviewedBy、每张图的源哈希、四类文字标签及冻结 aliases、人物框/personId、eventInstance（null 明确表示无事件）、预期未知及冲突维度。时间标签编码为 `role:precision:value`，例如 `event:year:2008`。人物 ID 不是模型生成的 faceId；用框 IoU≥0.5 作一对一检测匹配后才评价人物关系。该框评价规则仍需人工抽查，不是人脸识别结论。

truth 的可选 `taskOverrides: [{taskId, photos: [...]}]` 为指定增量任务覆盖部分照片的真值，其它照片沿用基线。补充说明前后可使用不同的可判断时间/事件真值，同时保持同一算法历史快照和整批预算；这些覆盖也须在执行前审阅、冻结并纳入真值文件哈希，不能看完模型输出再改答案。

具体材料与预算得到用户授权后，才能使用 `--execute --approval /绝对路径/approval.json`。审批记录绑定清单的**字节哈希**、模型、准确照片集、上限和到期时间，另含真实授权证据引用；脚本验证字段，不能验证“某人真的同意了”，因此不能由执行者自行生成批准冒充用户授权。仅这个分支会在实际调用时读取环境变量 `SGX_D4_API_KEY`；不打印、不写日志、不提交。

每次调用前检查授权记录未变、更改/删除/到期立即停止；所有任务共享剩余额度，不会每个任务重新获得 300 次。收到错误状态、非法/缺失输出、模型版本不一致、预算超出或超时便停止；计分发现错人、错合并或声明不变项变化时先停止并人工复核。未启动任务保留为 not_run，不从分母删掉。

## 输出与结束标准

固定输出：preflight.json、manifest.json、approval-reference.json（哈希和证据引用，无密钥）、provider-responses.jsonl、result-任务ID.json、ledger.json、metrics.json、REPORT.md。包含家人资料的原始响应只保存在受控本地目录，不提交 Git。无真实运行时只有预检/阻塞报告，不能虚构业务结果。

分别报告五维正确/漏掉/误加，未知/冲突、处理失败；人物检测、身份候选和全体同人配对；事件类型及同次事件配对、错误合并/拆分/未分配；历史筛选漏召回；增量不变项检查；完整调用/图片重复发送/Token/时延/费用。评分脚本采用冻结标签/同义词，语义等价与不合理精度仍需人工复核。人工纠错操作次数由任务清单与人工记录补充，未自动推断“确认负担下降”。

一轮结束必须给出：固定分母报告、阻断问题清单、2–3 个最值得修复的问题，以及继续/调整/停止的建议。探索后冻结参数、标签与量化门槛，再用独立保留样本验收；未做保留集不能称算法达标。

当前待用户提供的仅是实际可用材料/外发与人物用途范围，以及对具体批次预算的批准。算法实现、预检、评分和文档已由 Codex 准备；数据库、Redis 或队列不需要用户为这轮实验搭建。
