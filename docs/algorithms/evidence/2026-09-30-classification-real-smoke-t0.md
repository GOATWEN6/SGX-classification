## 结论

单张图片的 T0 真实模型链路已经可以从本地页面运行：图片、用户文字和 final ASR 会在服务端组合，经真实 Qwen 模型提取人物区域、时间、地点、事件和场景，再经过本地证据 Guard、内容组织器，返回“AI 整理”的标题、摘要、标签和复核项。API key 未进入浏览器，失败不会自动重试，原始失败证据保留。

当前仍不能称为完整 T1 或生产闭环。页面一次只接收一张不超过 1 MiB 的图片；多图成组、后台任务生命周期、取消/撤权/晚到结果、人工动作和全栈存储还没有在真实 Provider 页面链中全部串通。

## 当前真实数据流

```text
本地页面上传 1 张图片
  + 可选用户文字
  + 可选 final ASR
        ↓
服务端 multipart 解析和 Evidence 构造
        ↓
Qwen3.7 Flash 真实视觉调用（凭据只在服务端）
        ↓
严格 JSON Schema + 来源引用 + 时间格式 + 不可信指令 Guard
        ↓
图片、文字、ASR 的候选观察合成
        ↓
规则组织器生成 AI 标题、摘要、时间线/筛选标签
        ↓
返回 succeeded / needs_review；候选不直接成为确认事实或长期 Memory
```

## 本轮修复的代码问题

1. **时间格式适配**：模型返回有证据支持的 `YYYY-MM` 时，当前只支持年份的契约会机械降级为 `YYYY`。原始响应先落盘，便于审计。
2. **中文否定语义**：文本规则只从正向事件集合中产生主题；“不是毕业照”不再触发“毕业”。
3. **文字与 ASR 证据绑定**：优先在模型声明的 `user_text` 或 `final_asr` 来源内唯一匹配；该来源不存在时才允许全局唯一回退；同一来源有多个匹配时继续拒绝，防止猜测引用。

## 已验证的能力

- 真实模型和真实 HTTP 请求已运行，不是 Fake Provider 或保存响应回放。
- 图片、文字和 final ASR 可以共同支持同一事件与时间候选。
- 纯图片缺少事件证据时可以少判断，而不是强行补全所有维度。
- 信息冲突会进入 `needs_review`。
- 图片里的提示注入不会直接改变业务事件分类。
- 人物检测只产生未命名区域；本轮没有人物身份或亲属关系匹配。
- 每次调用都记录模型、Prompt、Token、费用、时延、输入哈希和原始响应。
