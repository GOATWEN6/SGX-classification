# 数字相框、Android 与算法协作契约

> 文档状态：`draft_for_owner_review`
> 版本：`0.1.0`
> 日期：2026-09-04
> 主要读者：硬件、Android、嵌入式、后端、算法、测试与运维团队

## 1. 文档目的

本文件说明数字相框和 Android 客户端怎样为五大算法提供稳定输入、接收结果并处理失败。它不是硬件选型书，也不要求 P0 立即自研相框硬件。当前产品仍优先使用 Android 平板或嵌入 Android App 的数字相框验证体验；未来更换主板、摄像头、麦克风或外壳时，算法接口保持不变。

## 2. 核心结论

硬件负责可靠采集、明确主体、缓存和传输；后端负责身份、权限、证据、任务和审计；算法负责从已授权证据生成候选结果。硬件不得直接连接模型供应商，也不得保存生产模型密钥。

当前可核验实现是 Android 平板上的 Web/PWA 形态，不是 Android Native 或自研硬件：浏览器已具备麦克风采集、实时语音和打断基础，但尚无独立设备凭证、持久弱网队列、可验证图库离线缓存和生产级 session 持久化。本文件同时描述当前兼容要求和未来硬件边界，不能把“契约已写”理解为“设备能力已实现”。

```text
传感器/相册/麦克风
      ↓
Android 采集与本地队列
      ↓ 受认证的上传与产品 API
产品后端
      ↓ 短期受控证据引用
算法 Provider
      ↓
候选结果 → 产品后端 → Android 展示/确认
```

## 3. 职责边界

| 组件 | 必须负责 | 不负责 |
|---|---|---|
| 数字相框硬件 | 麦克风、扬声器、屏幕、存储、网络、稳定供电、设备状态 | 人生事实判断、权限决策、认知诊断 |
| Android App | 授权提示、当前老人主体、采集、压缩、校验和、弱网队列、缓存、重试、状态展示 | 保存模型密钥、决定研究用途、直接写正式 Memory |
| 产品后端 | 认证、设备绑定、权限、对象存储、Evidence、任务编排、删除传播、审计 | 把未确认结果伪装成真实事实 |
| 算法层 | 分类、抽取、置信度、证据定位、拒判 | 直接联系家属、直接公开内容、绕过产品授权 |
| 科研侧 | 经同意的数据导出、离线分析、冻结评测 | 直接读取设备或线上产品数据库 |

## 4. 设备身份与老人主体

- `deviceId` 表示设备，不等于老人。
- `accountId` 表示登录身份，不等于内容主体。
- `subjectId` 表示内容进入哪位老人的生命记忆空间，所有算法请求必填；不要求该老人是群像中唯一人物。
- 夫妻共用一台相框时，可以采用大卡片、头像或语音辅助切换当前使用者；切换细节属于产品设计，但算法不得猜测主体。
- 无法确认当前主体时，允许浏览照片和使用不写长期 Memory 的普通功能；需要写入个人 Memory 或研究数据时必须先确认主体。
- 每个会话开始、恢复、设备重启后都要从后端恢复或重新确认有效主体，避免沿用错误账号。
- `actorId` 是操作账号，`deviceId` 是设备，`subjectId` 是被描述老人，`ownerId/contributorId` 管理原始素材权利；任何一项都不能互相替代。
- 确认个人 Memory 默认由内容主体执行；委托者/合法代理必须附带后端签发的 `authorityRef`。圈管理员不能因管理设备或成员而取得内容确认权。
- 群像照片使用一个主 `subjectId` 和多个 `depictedPersonRefs`；其他画面人物可以未知。无法选定当前老人时只能保留客户端本地 staging，不得提交 Evidence、运行分类或写入个人长期 Memory。

## 5. 设备能力描述

Android 首次绑定和能力变化时向后端报告 `DeviceCapabilities`：

```json
{
  "schemaVersion": "1.0",
  "deviceId": "frame_001",
  "appVersion": "1.0.0",
  "osVersion": "Android 14",
  "microphone": { "available": true, "sampleRates": [16000, 48000] },
  "camera": { "available": false },
  "storage": { "freeBytes": 1000000000 },
  "network": { "types": ["wifi"] },
  "onDeviceFeatures": ["sha256", "image_resize", "exif_read", "offline_queue"]
}
```

后端根据能力返回配置，而不是在 App 中硬编码供应商或阈值。能力上报不得包含与功能无关的设备指纹。

## 6. 图片协作流程

### 6.1 客户端预处理

Android 可以执行低风险、确定性的端侧工作：

- 检查 MIME、尺寸、文件大小和基本可读性。
- 计算 SHA-256，辅助发现重复上传和传输损坏。
- 读取 EXIF 时间、方向和可选 GPS；原始 EXIF 只在用户允许的情况下作为受保护元数据上传。
- 生成上传缩略图或按后端配置压缩副本。
- 保存本地任务 ID、上传状态和重试次数。

原图是否上传、是否保留 GPS、压缩质量都由产品设置和授权决定，不能由算法 provider 决定。推荐做法是：端侧提取允许使用的时间/地点字段，分享和展示副本默认移除 EXIF/GPS；受保护原件是否保留元数据由明确设置决定。这样既支持时间/地点分类，也不会把精确位置随图片跨圈传播。

### 6.2 上传顺序

```text
1. `POST /api/v1/media/uploads:init`
2. 后端返回短期上传凭证和 contentId
3. Android 直传对象存储，支持分片或断点续传
4. Android 调用 `POST /api/v1/media/uploads/{uploadId}:complete`，提交文件哈希、尺寸和上传完成状态
5. 后端检查对象归属、MIME、大小，并使用对象存储 checksum 或服务端复算验证内容
6. 后端创建 EvidenceRecord，并在同一受控流程中异步创建 ClassificationJob
7. Android 查询或接收任务状态
8. 展示候选标签，允许授权人确认/修正
```

不得把大文件编码成 JSON 发送给分类 API，也不得使用长期公开 URL。

客户端不能直接创建 Evidence 或分类 Job；客户端哈希只是上传提示，后端校验结果才是完整性依据。内部手工重跑只能由受授权的运维命令发起。

### 6.3 离线和弱网

- 选择照片后立即显示“已加入待上传”，不把网络等待伪装成页面卡死。
- 本地队列状态至少包括 `queued`、`uploading`、`uploaded`、`processing`、`completed`、`retryable_error`、`permanent_error`。
- App 重启后恢复未完成任务；重复点击通过客户端任务 ID 和服务端幂等键去重。
- 弱网下先保证相框播放已缓存照片；分类结果可以延迟，不阻塞基础产品体验。
- 只有在 Wi-Fi、充电或用户允许时执行大文件后台上传的策略，应做成可配置项。

## 7. 语音协作流程

- 麦克风授权由 Android 明确请求，拒绝后仍可返回相框和浏览照片。
- 实时对话继续使用后端可信代理；客户端不得持有 ASR、LLM 或 TTS 的生产密钥。
- Android 负责采集和播放，后端负责 session、provider 和打断传递。
- 老人打断时，客户端立即停止本地播放，同时把 cancel/interrupt 传给后端，不能只隐藏字幕。
- 只有最终 ASR 转写进入分类和 Memory 候选；中间 partial transcript 不应形成长期事实。
- 音频质量信息应包括采样率、丢帧、噪声、VAD 结果和 ASR 置信度，供下游拒判。
- 分类失败不影响实时语音会话结束、退出和返回相框。

## 8. 端侧缓存与同步

- 相框缓存已授权的展示照片，离线时继续轮播。
- 每个缓存对象保存 `contentId`、版本、哈希和有效授权状态。
- 后端发出删除或权限撤回后，Android 应在下一次同步时停止展示并清理对应缓存。
- 回收站中的内容不再参与轮播、推理和推荐，但授权人可在保留期内恢复。
- 永久删除的缓存不能因旧离线队列再次上传；删除墓碑版本优先于旧上传任务。
- 同步冲突使用服务端版本号处理，不依赖设备本地时间判断最后写入者。
- 素材所有者可以删除自己上传的原件；内容主体可以撤回其个人 Memory 使用和可见范围。冲突时客户端先隐藏并停止处理，再等待后端的最终资源处置结果。

## 9. 隐私与安全

- 相框锁屏、系统通知和日志不能泄露敏感文字、健康信息或私密照片标题。
- 本地敏感缓存使用 Android 安全存储能力和应用私有目录；设备解绑后清理访问凭证和受保护缓存。
- 上传凭证必须短期、单对象或最小路径授权。
- 日志只记录 `requestId/contentId/errorCode` 等诊断信息，不记录完整转写或图片公开链接。
- 未经独立研究同意，设备不采集额外认知研究任务、被动监听或持续行为特征。
- 家庭成员拥有 App 使用权不等于自动获得老人所有内容权限。

## 10. 算法版本与客户端兼容

- App 只依赖 API `schemaVersion` 和稳定状态码，不依赖具体模型名称。
- 后端向旧客户端保持向后兼容；新增标签使用可忽略字段，不能让旧版 App 崩溃。
- 客户端展示未知 facet 时回退为“其他标签”，而不是丢弃整个结果。
- 算法版本切换、灰度和回滚在后端完成，不要求重新刷写硬件固件。
- 若未来增加端侧模型，仍需实现同一契约并记录 `provider=on_device`、模型版本和设备能力。

## 11. 建议性能预算

以下是设计目标，需要在真实设备和网络上校准，不是当前已验证指标：

| 交互 | 目标 |
|---|---|
| 点击上传后的本地状态反馈 | 500 ms 内 |
| 断网时进入相框和播放缓存照片 | 不依赖云端成功 |
| 上传失败后的可见恢复动作 | 错误出现后 1 秒内展示，恢复不超过一次明确点击 |
| 普通照片分类结果 | 后台完成，建议 60 秒内返回首批标签 |
| 打断本地音频 | 点击打断后 250 ms 内停止本地播放，并同步取消上游响应 |
| 本地删除/权限撤回 | 用户确认后 1 秒内停止展示和新处理 |
| 服务端删除受理 | 在线状态 5 秒内返回受理/失败；物理清理 SLA 在生产前冻结 |
| 离线删除 | 立即本地隐藏；恢复联网后的第一个同步批次优先发送墓碑 |

## 12. 运维遥测

设备仅上报完成运维所需的最小事件：

- 设备/app/协议版本。
- 上传开始、成功、失败及错误码。
- 断点续传和重复任务次数。
- 缓存同步版本和删除确认状态。
- 音频采集状态、丢帧率、播放/打断状态，不上报无关原声。
- 算法任务 ID、等待时间和结果状态，不在设备日志保存模型完整输出。

用户体验分析与认知研究事件必须分开命名、分开同意、分开存储。

## 13. 独立安全链路

跌倒、胸痛、自伤表达等紧急生命安全事件不得依赖分类归纳、Memory 或认知趋势算法。未来如果实现，应使用单独授权、单独状态机、明确联系人、人工/确定性复核和最小披露。本文件不授权自动报警。

## 14. 硬件/Android 验收清单

- [ ] 同一设备切换老人后，所有新证据使用正确 `subjectId`。
- [ ] 无法确认主体时不会写入个人长期 Memory。
- [ ] App 内没有模型供应商生产密钥。
- [ ] 图片上传支持哈希校验、重试和重复提交去重。
- [ ] 断网和 App 重启后能恢复队列。
- [ ] 分类服务失败时相框仍能播放缓存照片。
- [ ] 麦克风授权失败有清晰返回路径。
- [ ] 语音打断同时停止本地播放并取消上游响应。
- [ ] partial transcript 不形成长期 Memory。
- [ ] 删除、恢复、永久删除能同步到本地缓存。
- [ ] 客户端不能直接创建 Evidence/Job，服务端能拒绝伪造上传完成证明。
- [ ] 旧客户端能忽略未知标签和字段。
- [ ] 日志不含完整隐私内容和公开对象 URL。
- [ ] 研究采集关闭时不会产生研究数据。
- [ ] 紧急安全事件不与认知趋势模型共用触发链。
